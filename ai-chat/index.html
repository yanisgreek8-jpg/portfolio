How the real thing works

The demo above runs on scripted answers so it never breaks and costs nothing to host. In a live shop the same interface sits on top of a language model. This is the whole architecture — there is no hidden part.

What I need from you

Before the first day
  • A link to the shop and access to add one script tag
  • Your product list in any form — export, spreadsheet, or the site itself
  • Delivery, returns and payment rules written out once, however roughly
  • Where an unanswered question should land: an inbox, Slack, or a helpdesk
  • Ten to twenty real questions customers actually ask

How long it takes

Typical small shop
  • Days 1–2 — widget on a staging page, answering from your rules
  • Days 3–5 — catalogue and order lookup connected
  • Days 6–7 — handoff, logging and the owner dashboard
  • Week 2 — live on a slice of traffic, tuned against real conversations

What it costs to run

After launch, monthly
  • Model usage is charged per conversation, not per seat — fractions of a cent each for a shop this size
  • Hosting for the small server: the cheapest tier at any provider
  • No licence, no per-agent fee, nothing to renew
  • You own the code and the conversation log
Why the demo is scripted. A live key in a public portfolio page gets drained by the first bot that finds it, and then the demo is broken for every client who opens it afterwards. So the interface, the flows and the dashboard here are real and clickable, and the sentences are pre-written. On a paid project the same interface is wired to the model on your own server, where the key stays private.
